# Автотесты REST API Яндекс.Диска

Пример проекта API-автотестов на Python 3, `pytest` и `requests`.

Тесты работают с боевым REST API по адресу
`https://cloud-api.yandex.net`. Для интеграционных сценариев на Диске
создаётся уникальная папка `disk:/api-autotests-<uuid>`. После тестового
запуска она удаляется без помещения в Корзину.

## Что проверяется

| HTTP-метод | Эндпоинт | Сценарий |
|---|---|---|
| GET | `/v1/disk` | Получение данных о Диске и проверка схемы ответа |
| GET | `/v1/disk/resources` | Happy Path, `fields`, пагинация, Unicode, `400/401/404` |
| GET | `/v1/disk/resources/download` | Прямая ссылка, байты файла, ZIP каталога, `400/401/404` |
| GET | `/v1/disk/resources/upload` | Ссылка и PUT байтов, overwrite, Unicode, `400/401/409` |
| GET | `/v1/disk/resources/files` | Плоский список, сортировка, пагинация, media type, `400/401` |
| GET | `/v1/disk/resources/last-uploaded` | Последние файлы, порядок дат, media type, `400/401` |
| GET | `/v1/disk/resources/public` | Публичные ресурсы, type, пагинация, `fields`, `400/401` |
| GET | `/v1/disk/public/resources` | Публичные метаданные без OAuth, path, пагинация, `400/404` |
| GET | `/v1/disk/public/resources/download` | Публичное скачивание без OAuth, вложенные файлы, `400/404` |
| GET | `/v1/disk/trash/resources` | Корень и элементы Корзины, пагинация, сортировка, `400/401/404` |
| PATCH | `/v1/disk/resources` | Пользовательские свойства, merge/delete/no-op, `400/401/404/415` |
| PATCH | `/v1/disk/public/resources/public-settings` | Настройки публичной ссылки, `fields`, Unicode, `400/401/404/415` |
| PUT | `/v1/disk/resources` | Happy Path, вложенность, Unicode, `fields`, `400/401/409` |
| PUT | `/v1/disk/resources/publish` | Публикация, настройки доступа, идемпотентность, `400/401/404/415` |
| PUT | `/v1/disk/resources/unpublish` | Снятие публикации, идемпотентность, `400/401/404` |
| POST | `/v1/disk/resources/copy` | Файл/папка, async, overwrite, Unicode, `400/401/404/409` |
| POST | `/v1/disk/resources/move` | Файл/папка, async, overwrite, Unicode, `400/401/404/409` |
| POST | `/v1/disk/resources/upload` | Импорт по URL, async, коллизии, Unicode, `400/401/409` |
| POST | `/v1/disk/public/resources/save-to-disk` | Файл/папка, вложенный path, async, коллизии, `400/401/404` |
| DELETE | `/v1/disk/resources` | Корзина и permanent delete, async, md5, `400/401/404/409` |
| DELETE | `/v1/disk/trash/resources` | Точечная очистка Корзины, async, Unicode, `400/401/404` |

Помимо интеграционных сценариев в проекте есть unit-тесты HTTP-клиента:
они не требуют сети и проверяют URL, заголовок авторизации, параметры и
обработку ошибок.

### Матрица сценариев `/v1/disk/resources`

| Метод | Категория | Проверка | Ожидаемый результат |
|---|---|---|---|
| GET | Happy Path | Метаинформация существующей папки | `200`, корректные `path`, `name`, `type`, `_embedded` |
| GET | Позитивный | Ограничение ответа через `fields` | `200`, только запрошенные поля |
| GET | Позитивный | `limit`, `offset`, `sort` | Корректная страница вложенных ресурсов |
| GET | Краевой | Unicode и пробелы в пути | Ресурс найден, путь не искажён |
| GET | Краевой | `offset` больше числа элементов | `200`, пустой `items` |
| GET | Негативный | Нет обязательного `path` | `400 FieldValidationError` |
| GET | Негативный | Нечисловой `limit` | `400` и стандартная схема ошибки |
| GET | Негативный | Ресурс отсутствует | `404 DiskNotFoundError` |
| GET | Негативный | Невалидный OAuth-токен | `401 UnauthorizedError` |
| DELETE | Happy Path | `permanently=true` | `202` или `204`, затем ресурс получает `404` |
| DELETE | Позитивный | `permanently` не передан | Ресурс перемещён в Корзину и затем очищен тестом |
| DELETE | Позитивный | `force_async=true` для непустой папки | `202`, ссылка на операцию, успешное завершение |
| DELETE | Позитивный | Корректный `md5` файла | Файл удалён |
| DELETE | Негативный | `md5` передан для папки | `400`, папка сохранена |
| DELETE | Негативный | Неверный `md5` файла | `409`, файл сохранён |
| DELETE | Негативный | Нет обязательного `path` | `400 FieldValidationError` |
| DELETE | Негативный | Ресурс отсутствует | `404 DiskNotFoundError` |
| DELETE | Негативный | Невалидный OAuth-токен | `401`, ресурс сохранён |
| DELETE | Краевой | Повторное удаление | Первый запрос успешен, второй получает `404` |

Ответы `403`, `406`, `412`, `413`, `423`, `429`, `503` и `507` зависят
от тарифа, режима «только чтение», блокировки ресурса, формата ответа,
квот, свободного места и состояния сервиса. Они указаны в контракте
API, но намеренно не провоцируются live-тестами: такие проверки должны
выполняться на управляемом стенде или через стаб/мок соответствующего
ответа.

### Матрица сценариев PATCH и PUT

| Метод | Категория | Проверка | Ожидаемый результат |
|---|---|---|---|
| PATCH | Happy Path | Добавление `custom_properties` папке | `200`, свойства возвращены и сохранены |
| PATCH | Позитивный | Параметр `fields` | Только запрошенные поля |
| PATCH | Позитивный | Обновление пользовательских данных файла | `200`, тип ресурса `file` |
| PATCH | Краевой | Unicode и emoji в значении | Значение сохраняется без искажений |
| PATCH | Краевой | Перезапись одного ключа | Остальные ключи сохраняются |
| PATCH | Краевой | Значение `null` | Удаляется только указанный ключ |
| PATCH | Краевой | Пустой `custom_properties` | `200`, существующие данные не меняются |
| PATCH | Негативный | Нет обязательного `path` | `400 FieldValidationError` |
| PATCH | Негативный | `custom_properties` не объект | `400` и стандартная схема ошибки |
| PATCH | Краевой | Body отсутствует | Боевой API возвращает `200` и выполняет no-op |
| PATCH | Негативный | Ресурс отсутствует | `404 DiskNotFoundError` |
| PATCH | Негативный | Невалидный OAuth-токен | `401`, данные не изменены |
| PATCH | Негативный | `Content-Type: text/plain` | `415 Unsupported Media Type` |
| PUT | Happy Path | Папка внутри существующего родителя | `201`, Link и метаданные новой папки |
| PUT | Позитивный | Unicode и пробелы в пути | Путь и имя сохраняются без искажений |
| PUT | Позитивный | Параметр `fields` | Link содержит только запрошенные поля |
| PUT | Позитивный | Поэтапное создание вложенной папки | `201` после создания прямого родителя |
| PUT | Негативный | Нет обязательного `path` | `400 FieldValidationError` |
| PUT | Негативный | Передан пустой `path` | `400 FieldValidationError` |
| PUT | Негативный | Прямой родитель отсутствует | `409 DiskPathDoesntExistsError` |
| PUT | Негативный | Папка уже существует | `409 DiskPathPointsToExistentDirectoryError` |
| PUT | Негативный | Невалидный OAuth-токен | `401 UnauthorizedError` |
| PUT | Краевой | Попытка создать `disk:/` | `409 DiskPathDoesntExistsError` |

Полигон указывает body PATCH как обязательное, однако боевой API
возвращает `200` и выполняет no-op, если body отсутствует. Для PUT
полигон перечисляет общий ответ `404`, однако боевой API возвращает
`409 DiskPathDoesntExistsError`, если прямой родитель не существует.
Тесты закрепляют фактический контракт сервиса.

| public | Негативный | Невалидный OAuth-токен | `401 UnauthorizedError` |

Боевой API отвечает `409 DiskPathDoesntExistsError` при попытке
переместить папку внутрь собственного существующего подкаталога, хотя
полигон связывает неправильное новое положение с `403`. Тест закрепляет
наблюдаемое поведение и отдельно проверяет, что исходная структура не
изменилась.

Список public глобальный и не принимает `path`: тесты находят только
свои ресурсы по уникальному полному пути. Они публикуют исключительно
временные ресурсы песочницы и всегда снимают с них публикацию. Поэтому
результат не зависит от уже опубликованных данных аккаунта.

| Ручка | Категория | Проверка | Ожидаемый результат |
|---|---|---|---|
| publish | Happy Path | Публикация существующей приватной папки | `200`, Link, появляются `public_key` и `public_url` |
| publish | Позитивный | Публикация файла с `read_only=true` | JSON-body принят, файл становится публичным |
| publish | Позитивный | `allow_address_access=true` | Параметр принят, ресурс опубликован |
| publish | Позитивный | Параметр `fields` | Link содержит только запрошенные поля |
| publish | Краевой | Unicode и пробелы в пути | Путь не искажён |
| publish | Краевой | Повторная публикация | `200`, публичные ключ и URL не меняются |
| publish | Краевой | Body отсутствует | Боевой API применяет настройки по умолчанию и возвращает `200` |
| publish | Негативный | Нет обязательного `path` | `400 FieldValidationError` |
| publish | Негативный | Ресурс отсутствует | `404 DiskNotFoundError` |
| publish | Негативный | `public_settings` не является объектом | `400` и стандартная схема ошибки |
| publish | Негативный | `Content-Type: text/plain` | `415 Unsupported Media Type` |
| publish | Негативный | Невалидный OAuth-токен | `401`, ресурс остаётся приватным |
| unpublish | Happy Path | Снятие ссылки с опубликованной папки | `200`, `public_key/public_url` исчезают |
| unpublish | Позитивный | Снятие ссылки с файла | Файл и его содержимое сохранены |
| unpublish | Позитивный | Параметр `fields` | Link содержит только запрошенные поля |
| unpublish | Краевой | Unicode и пробелы в пути | Путь не искажён |
| unpublish | Краевой | Уже приватный ресурс | Идемпотентный ответ `200` |
| unpublish | Краевой | Повторный unpublish | Оба запроса получают `200`, ресурс приватный |
| unpublish | Негативный | Нет обязательного `path` | `400 FieldValidationError` |
| unpublish | Негативный | Ресурс отсутствует | `404 DiskNotFoundError` |
| unpublish | Негативный | Невалидный OAuth-токен | `401`, публичная ссылка сохраняется |

Полигон помечает body publish как обязательный, однако боевой API
принимает запрос без тела и публикует ресурс с настройками по умолчанию.
Unpublish также идемпотентен для существующего ресурса: уже приватный
ресурс и повторный запрос получают `200`. Тесты закрепляют это
наблюдаемое поведение.

Все тестовые публичные ссылки снимаются в блоках `finally`, включая
сценарии, в которых проверка завершилась неуспешно. Настройки
`read_only=true` не предоставляют публичный доступ на запись.

### Матрица сценариев GET и POST upload

| Метод | Категория | Проверка | Ожидаемый результат |
|---|---|---|---|
| GET | Happy Path | Получение URL и PUT точных байтов | Link `200`, загрузка `201`, совпадают `md5` и `size` |
| GET | Позитивный | Параметр `fields` | Link ограничен полями, URL остаётся рабочим |
| GET | Позитивный | `overwrite=true` | Существующий файл полностью заменён |
| GET | Краевой | Unicode и пробелы в пути | Путь и имя не искажены |
| GET | Краевой | Пустой файл | Создан файл размера 0 с корректным `md5` |
| GET | Негативный | Файл существует, overwrite не задан | `409`, исходные данные сохранены |
| GET | Негативный | Нет обязательного `path` | `400 FieldValidationError` |
| GET | Негативный | Прямой родитель отсутствует | `409 DiskPathDoesntExistsError` |
| GET | Негативный | Попытка заменить каталог файлом | `409`, каталог сохранён |
| GET | Негативный | Невалидный OAuth-токен | `401 UnauthorizedError` |
| POST | Happy Path | Импорт неизменяемого публичного файла | `202`, операция success, точные байты загружены |
| POST | Позитивный | Параметр `fields` | Ограниченный Link сохраняет URL операции |
| POST | Позитивный | `disable_redirects=true` для прямого URL | Импорт успешно завершается |
| POST | Краевой | Unicode и пробелы в пути | Путь и имя не искажены |
| POST | Краевой | Путь занят файлом | Исходный файл сохранён, импорт создан как `name (1).ext` |
| POST | Краевой | Путь занят каталогом | Каталог сохранён, импорт создан рядом как `name (1)` |
| POST | Негативный | Нет обязательного `path` или `url` | `400 FieldValidationError` |
| POST | Негативный | URL не является абсолютным | `400` и стандартная схема ошибки |
| POST | Негативный | Прямой родитель отсутствует | `409 DiskPathDoesntExistsError` |
| POST | Негативный | Невалидный OAuth-токен | `401 UnauthorizedError` |

При GET upload OAuth используется только для получения временной ссылки:
PUT с содержимым выполняется отдельной сессией без передачи OAuth-заголовка.
POST-тесты импортируют файл из конкретного Git-коммита, поэтому внешний
контент неизменяем и его хеш можно проверять точно.

Для POST полигон перечисляет `409` при занятом пути, однако боевой API
принимает запрос с `202`, завершает операцию успешно и автоматически
добавляет новому файлу суффикс ` (1)`. Тесты отдельно проверяют коллизии
с файлом и каталогом, а также сохранность исходного ресурса.

Обе публичные ручки вызываются клиентом без заголовка Authorization.
OAuth применяется только для подготовки и последующей очистки временных
ресурсов. Прямые ссылки также скачиваются отдельной сессией без OAuth.

Боевой API всегда добавляет `_embedded.public_key` в ответ каталога,
даже если это поле не указано в `fields`. Кроме того, произвольная
непустая строка считается допустимым форматом ключа и получает `404`;
`400` возвращается для отсутствующего или явно пустого значения.

тесты создают ресурсы с уникальными именами и ищут их по полному пути,
не предполагая, что аккаунт пустой. Документированный `404` нельзя
детерминированно вызвать входными параметрами этих методов; его следует
проверять на управляемом стенде или стабом ответа.

| Ручка | Категория | Проверка | Ожидаемый результат |
|---|---|---|---|

| public-settings | Позитивный | Настройки опубликованного файла | `200`, публичный файл остаётся доступен |

| save-to-disk | Краевой | Имя в целевой папке занято | `201`, копия получает суффикс ` (1)`, исходник не перезаписан |

| save-to-disk | Негативный | Неизвестный ключ | `404` |

| save-to-disk | Негативный | Целевая папка отсутствует | `404/409`, ресурс не создаётся |
| save-to-disk | Негативный | Невалидный OAuth-токен | `401` |

Позитивные проверки `public-settings` являются capability-aware: на аккаунте,
поддерживающем расширенные публичные настройки, они строго требуют `200`.
Текущий обычный аккаунт после успешной публикации отвечает для валидного PATCH
`404 DiskNotFoundError`; только эти пять сценариев в таком окружении помечаются
`SKIPPED`, а все детерминированные негативные проверки выполняются.

Все `save-to-disk`-тесты явно передают `save_path` внутри временной песочницы,
поэтому не затрагивают пользовательскую папку «Загрузки». Боевой API при занятом
имени не возвращает перечисленный в полигоне `409`, а безопасно добавляет
суффикс ` (1)`; тест закрепляет это фактическое поведение.

### Матрица сценариев Корзины

| Метод | Категория | Проверка | Ожидаемый результат |
|---|---|---|---|
| GET | Happy Path | Корень Корзины без `path` | `200`, `trash:/`, тестовый элемент в `_embedded` |
| GET | Happy Path | Метаданные удалённого файла | `origin_path`, `deleted`, `md5` и `size` корректны |
| GET | Позитивный | Удалённая папка с файлами | Вложенные элементы доступны через `_embedded` |
| GET | Позитивный | Параметр `fields` | Возвращены только запрошенные атрибуты |
| GET | Позитивный | `limit`, `offset`, `sort=created` | Непересекающиеся страницы в порядке даты |
| GET | Краевой | `offset=1000000` | `200`, пустой `items` |
| GET | Краевой | Unicode и пробелы | Имя и `origin_path` не искажены |
| GET | Негативный | Нечисловой `limit` или `offset` | `400` и стандартная схема ошибки |
| GET | Негативный | Неподдерживаемый `sort=name` | `400 FieldValidationError` |
| GET | Негативный | Ресурс Корзины отсутствует | `404 DiskNotFoundError` |
| GET | Негативный | Невалидный OAuth-токен | `401 UnauthorizedError` |
| DELETE | Happy Path | Удалить выбранный файл из Корзины | `202/204`, затем ресурс получает `404` |
| DELETE | Позитивный | Удалить папку с вложенным файлом | Вся тестовая структура удалена |
| DELETE | Позитивный | `force_async=true` | `202`, операция завершается успешно |
| DELETE | Краевой | `fields=href,method` | Боевой API сохраняет обязательный `templated` в Link |
| DELETE | Краевой | Unicode в `trash_path` | Ресурс успешно удалён |
| DELETE | Краевой | Повторное удаление | Первый запрос успешен, второй получает `404` |
| DELETE | Негативный | Ресурс Корзины отсутствует | `404 DiskNotFoundError` |
| DELETE | Негативный | Невалидный `force_async` | `400`, ресурс сохранён |
| DELETE | Негативный | Невалидный OAuth-токен | `401`, ресурс сохранён |

Полная очистка Корзины через DELETE без `path` или с `path=trash:/` необратимо
затронула бы пользовательские данные. Поэтому форма такого HTTP-запроса
проверяется unit-тестом с mock-сессией, а live-тесты всегда передают путь
элемента, созданного текущим тестом. Ответы `403/406/412/413/423/429/503`
зависят от тарифа и состояния сервиса и должны проверяться на управляемом стенде.

## Требования

- Python 3.10 или новее;
- OAuth-токен Яндекс.Диска с правами на чтение и запись — только для
  интеграционных тестов.

Токен нельзя добавлять в исходный код, `.env`, коммиты или логи. Проект
получает его исключительно из переменной окружения
`YANDEX_DISK_TOKEN`.

## Локальный запуск

Создайте виртуальное окружение и установите зависимости:

```bash
python -m venv .venv
```

Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
$env:YANDEX_DISK_TOKEN = "ваш_OAuth_токен"
pytest
```

Linux/macOS:

```bash
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
export YANDEX_DISK_TOKEN="ваш_OAuth_токен"
pytest
```

Полезные команды:

```bash
# Только быстрые unit-тесты, сеть и токен не нужны
pytest tests/unit

# Только тесты реального API
pytest -m integration

# Проверка стиля
ruff check .
ruff format --check .
```

Если `YANDEX_DISK_TOKEN` не задан, интеграционные тесты будут отмечены
как `SKIPPED`, а unit-тесты продолжат выполняться.

## CI

GitHub Actions запускает тесты и `ruff` на Python 3.10 и 3.12. Unit-тесты
выполняются всегда, в том числе для pull request. Интеграционные тесты
запускаются для `push` и вручную, если в настройках репозитория создан
Actions secret `YANDEX_DISK_TOKEN`; без него они безопасно пропускаются.
